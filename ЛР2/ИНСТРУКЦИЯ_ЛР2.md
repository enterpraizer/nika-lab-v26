# ЛР №2 — перенос и тестирование классификации

Предметная область «Языки программирования», вариант 26.
Wit.ai не используется: классификация выполняется логическими правилами
через штатный механизм `lr_alternative_classification`.

---

## Что сгенерировано

```
kb/extra/section_subject_domain_of_programming_languages/
├── messages/
│   └── concept_message_about_author.scs        наш класс сообщений
├── logic_rules/
│   ├── classification/                          67 правил .gwf
│   │   ├── lr_classify_what_is_*.gwf            58 шт.
│   │   ├── lr_classify_subdividing_of_*.gwf      2 шт.
│   │   └── lr_classify_author_of_*.gwf           7 шт.

```

### Почему понадобились фраза и правило ответа

Классификация и ответ — разные вещи:

```
классификация  → система поняла: это вопрос об авторе, сущность Python
правило ответа → что искать в базе, чтобы ответить
фраза ответа   → как сформулировать ответ словами
```

Первые два типа вопросов отвечают сразу, потому что используют **штатные**
классы `concept_message_about_entity` и `concept_message_about_subdividing` —
правила ответа и фразы для них уже лежат в базе NIKA.

Третий тип использует **свой** класс `concept_message_about_author`, для
которого в базе нет ничего. Поэтому добавлены правило ответа и две фразы:

```
Автор языка программирования ${_language_name} — ${_author_name}.
Язык программирования ${_language_name} создал ${_author_name}.
```

Формально это работа ЛР3, но без них вопрос об авторе не отвечает.

### Три типа вопросов

| Тип | Класс сообщения | Правил | Формулировки |
|---|---|---|---|
| Что такое …? | `concept_message_about_entity` (штатный) | 58 | «Что такое компилятор?» / «Что значит компилятор?»; для людей — «Кто такой Гвидо ван Россум?» / «Кто это Гвидо ван Россум?» |
| На что декомпозируется …? | `concept_message_about_subdividing` (штатный) | 2 | «На что декомпозируется язык программирования?» / «Каким бывает …?» |
| Кто создал …? | `concept_message_about_author` (**свой**) | 7 | «Кто создал Python?» / «Кто автор Python?» |

### Как устроено правило

Каждый файл — клон штатного шаблона
`lr_alternative_classification/lr_message_about_entity.gwf`
с подменёнными идентификаторами. Логика:

```
ЕСЛИ текст сообщения = «Что такое компилятор?»
  ИЛИ текст сообщения = «Что значит компилятор?»
ТО  сообщение ∈ concept_message_about_entity
    сообщение → rrel_entity → concept_compiler
```

Правило входит в множество `concept_classify_message_rule_priority_1` —
его читает штатный агент альтернативной классификации.

## 5. Тест классификации

Открыть **localhost:3033** и задать вопрос:

```
Что такое компилятор?
```

Теперь система должна **ответить по существу** на все три типа:

```
Что такое компилятор?
  → компилятор - Компилятор — программа, переводящая исходный текст ...

Кто создал Python?
  → Автор языка программирования Python — Гвидо ван Россум.

На что декомпозируется язык программирования?
  → язык программирования разбивается на логический язык программирования,
    процедурный язык программирования, функциональный язык программирования,
    объектно-ориентированный язык программирования.
```

Если вопрос об авторе получает фразу непонимания («Сформулируйте, пожалуйста,
по-другому», «Извините, я не знаю, как ответить») —
значит не подхватились правило ответа или фраза. Проверить:

```bash
docker compose logs problem-solver | grep -iE "lr_answer_about_author|phrase_about_author"
```

Вернуться в **sc-web** и открыть:

```
concept_message_about_entity
```

В списке элементов `∋` должно появиться отправленное сообщение.
Открыть его — у сообщения должна быть связь `rrel_entity`
к `concept_compiler`.

Это и есть доказательство, что классификация сработала.

**Рисунок 6 отчёта.**

## Если классификация не срабатывает

Логи агента классификации:

```bash
docker compose logs problem-solver | grep -i "classif"
```

Порядок перезапуска: сначала решатель, дождаться `healthy`, потом
python-агенты.

```bash
docker compose restart py-sc-server
```

**Менять `nika.ini` не нужно.** Проверено на чистом клоне ветки `tpis-2023`:
со штатным токеном всё работает. Агент альтернативной классификации стоит в
программе обработки сообщения первым, к Wit.ai система обращается, только если
ни одно правило не сработало.

**Если Ника не ответила.** В решателе NIKA есть ошибка: готовый ответ иногда
теряется (в логе `Generated text: ...`, сразу за ним `Reply message not generated`).
Лечится повтором того же вопроса. Следующий вопрос задавать только после ответа
на предыдущий. Если Ника перестала отвечать совсем — решатель завис:

```bash
docker compose restart problem-solver
docker compose restart py-sc-server
```

Перезапускать именно в таком порядке и оба: без второго Ника вечно «печатает».

## Сценарий диалога для отчёта

Ответы приведены дословно, как их выдаёт Ника (прогон 5 октября 2026).

```
1. Пользователь: Что такое компилятор?
2. Ника: компилятор - Компилятор — программа, переводящая исходный текст программы с языка программирования в эквивалентный код на языке более низкого уровня, чаще всего в машинный код..

3. Пользователь: Кто создал Python?
4. Ника: Автор языка программирования Python — Гвидо ван Россум.

5. Пользователь: На что декомпозируется язык программирования?
6. Ника: язык программирования разбивается на логический язык программирования, процедурный язык программирования, функциональный язык программирования, объектно-ориентированный язык программирования.

7. Пользователь: Что такое виртуальная машина?
8. Ника: виртуальная машина - Виртуальная машина — программная среда, исполняющая программы, представленные в виде промежуточного (байт-)кода, и изолирующая их от конкретной аппаратной платформы..
```

Восемь сообщений: четыре вопроса и четыре ответа, как требует задание.
Двойная точка в конце ответов «Что такое …» — от штатной фразы NIKA
`${_entity_note_name} - ${_note}.`: она добавляет точку к описанию, которое
уже заканчивается точкой. На вопрос о декомпозиции Ника выводит одно из
четырёх разбиений.
