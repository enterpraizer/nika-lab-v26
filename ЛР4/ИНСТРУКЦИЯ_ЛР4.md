## Запуск

```bash
cd nika
docker compose up -d --no-build
```

Образы стандартные, ничего собирать не нужно: код агента берётся из папки
`problem-solver/py` через том из `docker-compose.override.yml`. Через 2–3 минуты:

```bash
docker compose logs problem-solver | grep -E "\[[0-9]+/[0-9]+\]" | tail -1
docker compose logs py-sc-server | grep -E "TiobeRatingModule|Registered modules"
```

В первой строке два одинаковых числа (`[1868/1868]`), во втором выводе — `TiobeRatingModule | Registered`
и `Registered modules successfully`.

Если после правки кода агента он не подхватился:

```bash
docker compose restart problem-solver
docker compose restart py-sc-server
```

Обе команды и именно в таком порядке: `py-sc-server` сам не переподключается к перезапущенному решателю.

## Интернет и запасная копия

Агент скачивает `https://www.tiobe.com/tiobe-index/`. Если интернета нет или сайт поменял вёрстку,
агент берёт копию таблиц `problem-solver/py/modules/tiobeRatingModule/data/tiobe_snapshot.html`
(рейтинг за октябрь 2026 года) и пишет в журнал `read_page snapshot`. Ответ в чате будет и так.

Для опытов адрес задаётся переменной окружения `TIOBE_URL` контейнера `py-sc-server`
(например, несуществующий адрес — чтобы показать работу по копии).
